# 10. Тестирование и приемка

## Подход к тестированию

Проект проверяется на нескольких уровнях:

- автоматические Django-тесты для ключевой бизнес-логики;
- ручная проверка пользовательских сценариев через интерфейс;
- проверка отчетов и экспортов;
- проверка демоданных;
- проверка миграций и системной конфигурации.

## Что покрыто автоматическими тестами

В проекте есть тесты для следующих сценариев:

- создание истории статуса при создании заявки;
- доступность карточки заявки;
- сохранение даты перевозки при редактировании;
- автоматический расчет стоимости при пустом поле стоимости;
- расчет стоимости по объему;
- сохранение ручной стоимости;
- перерасчет автостоимости при изменении веса;
- запрет повторного назначения занятого водителя и ТС;
- назначение ТС как частичного покрытия груза;
- расчет нескольких рейсов и километража;
- назначение нескольких ТС на одну заявку;
- изменение массы после назначения;
- архивирование завершенной заявки;
- расчет показателей отчетности;
- экспорт PDF;
- экспорт Excel;
- повторяемость демоданных.

## Команды проверки

```bash
python manage.py check
python manage.py test
python manage.py migrate
python manage.py seed_demo
```

| ID | Сценарий | Шаги | Ожидаемый результат |
|---|---|---|---|

| TC-05 | Авторасчет стоимости по объему | Указать тип груза и объем, массу оставить пустой | Стоимость рассчитана по объему |
| TC-06 | Ручная стоимость | Ввести стоимость вручную | Система сохраняет ручную стоимость и не перезаписывает ее |
| TC-07 | Назначение одного ТС | Открыть заявку, добавить ТС и водителя | В карточке заявки отображается назначенная перевозка |
| TC-08 | Назначение нескольких ТС | Добавить второе ТС к той же заявке | В карточке заявки отображаются две перевозки |
| TC-09 | Занятый водитель | Попробовать назначить занятого водителя в другую активную заявку | Система показывает ошибку занятости |
| TC-10 | Занятое ТС | Попробовать назначить занятое ТС в другую активную заявку | Система показывает ошибку занятости |
| TC-11 | Расчет километража | Указать 3 плеча и количество рейсов | Система показывает общий километраж |
| TC-12 | История статусов | Изменить статус заявки | В карточке появляется новая запись истории |
| TC-13 | Архивирование | Установить статус completed или cancelled | Заявка попадает в архив |
| TC-14 | Отчетность | Открыть отчеты с фильтрами | Система показывает карточки, таблицы и диаграммы |
| TC-15 | PDF-экспорт | Нажать «Скачать PDF» | Загружается PDF-файл |
| TC-16 | Excel-экспорт | Нажать «Скачать Excel» | Загружается XLSX-файл |

## Критерии приемки

Система считается готовой к демонстрации, если:

- пользователь может авторизоваться;
- демоданные создаются без ошибок;
- заявка создается только при выборе статуса;
- стоимость считается автоматически, если не задана вручную;
- ручная стоимость не перезаписывается;
- можно назначить несколько ТС на одну заявку;
- занятые водитель и ТС не назначаются в другую активную перевозку;
- история статусов сохраняется;
- отчеты открываются;
- PDF и Excel формируются;
- автоматические тесты проходят успешно.

## Риски тестирования

- Километраж вводится вручную, поэтому корректность расстояний зависит от пользователя.
- В проекте нет внешнего API карт, поэтому автоматическая проверка расстояний не выполняется.
- Водитель не имеет отдельного интерфейса подтверждения выполнения рейса.
