# 05. Use cases

## UC-01. Создание заявки

**Цель:** зарегистрировать заявку клиента на грузоперевозку.

**Актор:** менеджер по логистике.

**Предусловия:**

- менеджер авторизован;
- клиент существует в системе или будет создан заранее;
- в системе есть справочник статусов.

**Основной сценарий:**

1. Менеджер открывает раздел заявок.
2. Нажимает «Создать заявку».
3. Выбирает клиента.
4. Указывает тип груза.
5. Заполняет описание груза.
6. Указывает массу или объем.
7. Заполняет адрес загрузки и адрес выгрузки.
8. Указывает дату перевозки.
9. Выбирает статус заявки.
10. При необходимости вводит стоимость вручную.
11. Сохраняет заявку.

**Результат:** заявка создана, статус записан в историю.

**Альтернативы:**

- Если стоимость не указана, система рассчитывает ее автоматически.
- Если масса и объем не указаны, система показывает ошибку.
- Если статус не выбран, система не сохраняет заявку.

## UC-02. Назначение транспорта и водителя

**Цель:** закрепить исполнителя и транспорт за заявкой.

**Актор:** менеджер по логистике.

**Предусловия:**

- заявка существует;
- заявка не находится в архиве;
- заявка не завершена и не отменена;
- водитель и ТС доступны.

**Основной сценарий:**

1. Менеджер открывает карточку заявки.
2. Нажимает «Добавить ТС».
3. Выбирает водителя.
4. Выбирает транспортное средство.
5. Указывает количество рейсов.
6. Указывает три плеча маршрута.
7. Сохраняет назначение.

**Результат:** создается перевозка, связанная с заявкой.

**Альтернативы:**

- Если водитель занят, система показывает ошибку.
- Если ТС занято, система показывает ошибку.
- Если одной машины недостаточно, менеджер может добавить еще одно ТС к той же заявке.

## UC-03. Изменение статуса заявки

**Цель:** зафиксировать переход заявки на следующий этап обработки.

**Актор:** менеджер по логистике.

**Предусловия:**

- заявка существует;
- менеджер авторизован.

**Основной сценарий:**

1. Менеджер открывает редактирование заявки.
2. Выбирает новый статус.
3. Сохраняет заявку.
4. Система создает запись в истории статусов.

**Результат:** статус заявки обновлен, изменение отражено в истории.

**Альтернативы:**

- Если выбран статус completed или cancelled, система архивирует заявку.

## UC-04. Расчет стоимости

**Цель:** получить итоговую стоимость перевозки на основании груза и километража.

**Актор:** система.

**Предусловия:**

- в заявке указан тип груза;
- указана масса или объем;
- стоимость не введена вручную.

**Основной сценарий:**

1. Система определяет тип груза.
2. Система выбирает тариф за тонну или м3.
3. Если указана масса, используется масса.
4. Если масса не указана, используется объем.
5. Система рассчитывает стоимость груза.
6. Система суммирует километраж всех назначенных ТС.
7. Система рассчитывает стоимость километража.
8. Система сохраняет итоговую стоимость.

**Формулы:**

```text
стоимость_груза = базовая_ставка + масса * тариф_за_тонну
```

```text
стоимость_груза = базовая_ставка + объем * тариф_за_м3
```

```text
общий_км_ТС = плечо_1 + плечо_2 * рейсы + плечо_3 * (рейсы - 1)
```

```text
итоговая_стоимость = стоимость_груза + сумма(общий_км_ТС * 100)
```

**Альтернативы:**

- Если стоимость введена вручную, система не перезаписывает ее.

## UC-05. Формирование отчета

**Цель:** получить аналитическую сводку по заявкам и перевозкам.

**Актор:** менеджер или руководитель.

**Предусловия:**

- пользователь авторизован;
- в системе есть заявки.

**Основной сценарий:**

1. Пользователь открывает раздел отчетов.
2. Указывает фильтры: период, статус, клиент, тип груза.
3. Система строит показатели и таблицы.
4. Система отображает диаграммы.
5. Пользователь при необходимости выгружает отчет в PDF или Excel.

**Результат:** пользователь получает отчет по заявкам, статусам, выполненным перевозкам и загрузке водителей.

## UC-06. Архивирование заявки

**Цель:** убрать завершенную или отмененную заявку из активного списка.

**Актор:** система.

**Предусловия:**

- заявка существует;
- статус изменен на completed или cancelled.

**Основной сценарий:**

1. Менеджер выбирает статус completed или cancelled.
2. Система сохраняет заявку.
3. Система устанавливает признак архива.
4. Заявка исчезает из активного списка.
5. Заявка становится доступна в разделе архива.

**Результат:** активный список содержит только незавершенные заявки.
