ОПИСАНИЕ ДОРАБОТОК DJANGO-ПРОЕКТА "СИСТЕМА УПРАВЛЕНИЯ ГРУЗОПЕРЕВОЗКАМИ"

Проект: система управления грузоперевозками для менеджера по логистике.
Основное приложение: logistics.
Стек: Django, SQLite, Django Templates, Bootstrap 5, Chart.js.

Исходные основные сущности проекта:
- Profile
- Client
- Driver
- Vehicle
- RequestStatus
- TransportationRequest
- RequestStatusHistory
- Transportation

Исходная бизнес-логика проекта:
- у заявки должна быть указана хотя бы масса или объем груза;
- статусы completed и cancelled автоматически архивируют заявку;
- ведется история изменения статусов заявки;
- нельзя назначить занятого водителя или занятый транспорт в другую активную перевозку;
- в проекте есть разделы dashboard, заявки, карточка заявки, перевозки, отчеты.


1. АВТОМАТИЧЕСКИЙ РАСЧЕТ СТОИМОСТИ ПЕРЕВОЗКИ

В модель TransportationRequest добавлена логика автоматического расчета стоимости перевозки.
Существующее поле cost сохранено. Новая таблица тарифов не создавалась, потому что для учебного дипломного проекта выбран простой вариант с тарифами в коде.

Первоначальная базовая логика:

Если указана масса груза:
cost = base_rate + cargo_weight * rate_per_ton

Если масса не указана, но указан объем:
cost = base_rate + cargo_volume * rate_per_m3

Если указаны и масса, и объем:
приоритет имеет масса.

Если пользователь сам ввел стоимость:
автоматический расчет ее не перезаписывает.

Базовая ставка:
base_rate = 2000 руб.


2. ТИПЫ ГРУЗА И ТАРИФЫ

После обсуждения расчет стоимости был улучшен: добавлено поле "Тип груза".

В TransportationRequest добавлено поле cargo_type.

Доступные типы груза:
- Песок
- Щебень
- Бетон

Для каждого типа груза задан свой тариф.

Тарифы:
Песок:
- 550 руб./т
- 350 руб./м3

Щебень:
- 650 руб./т
- 420 руб./м3

Бетон:
- 1200 руб./т
- 900 руб./м3

Итоговая формула:
стоимость = базовая ставка + количество * тариф выбранного типа груза

Если указана масса:
cost = base_rate + cargo_weight * rate_per_ton_for_cargo_type

Если масса не указана, но указан объем:
cost = base_rate + cargo_volume * rate_per_m3_for_cargo_type

Если указаны и масса, и объем:
используется масса.

Пример 1:
Тип груза: Бетон
Масса: 8.5 т
cost = 2000 + 8.5 * 1200 = 12200 руб.

Пример 2:
Тип груза: Песок
Объем: 10 м3
cost = 2000 + 10 * 350 = 5500 руб.

Пример 3:
Тип груза: Щебень
Масса: 12.7 т
cost = 2000 + 12.7 * 650 = 10255 руб.

В модели добавлены:
- calculate_cost()
- get_cargo_rates()
- cargo_tariff_summary

В метод save() добавлена автоподстановка стоимости, если поле cost не заполнено.

6. РАСЧЕТ ЗАГРУЗКИ ТРАНСПОРТА

Добавлен расчет загрузки транспортного средства по массе груза.

Используются существующие поля:
- cargo_weight в заявке;
- capacity_tons у транспортного средства.

Формула:
load_percent = cargo_weight / capacity_tons * 100

Пример:
масса груза = 8 т
грузоподъемность транспорта = 10 т

load_percent = 8 / 10 * 100 = 80%

Загрузка транспорта не хранится отдельным полем в базе данных.
Она вычисляется динамически, потому что зависит от уже существующих данных.

Если масса груза не указана:
- расчет загрузки не выполняется;
- назначение транспорта разрешается.

Если масса груза превышает грузоподъемность транспорта:
- назначение запрещается;
- в интерфейсе выводится сообщение:
"Выбранное транспортное средство не подходит по грузоподъемности."

Проверка выполняется:
- в форме назначения перевозки;
- в модели Transportation через clean().

Процент загрузки отображается:
- в форме назначения перевозки;
- в карточке заявки;
- в карточке перевозки.


7. АНАЛИТИЧЕСКИЕ ПОКАЗАТЕЛИ В ОТЧЕТНОСТИ

Доработан reports_view.

Добавлены новые расчетные показатели:
- средняя стоимость заявки;
- процент выполненных заявок;
- количество просроченных заявок;
- количество активных заявок в срок;
- загрузка водителей.

Средняя стоимость:
average_request_cost = avg(cost)

Процент выполненных заявок:
completed_request_percent = completed_request_count / request_total_count * 100

Если заявок нет:
completed_request_percent = 0

Просроченная заявка:
заявка считается просроченной, если дата перевозки уже прошла, а статус не completed и не cancelled.

Условие:
transportation_date < today
status not in ['completed', 'cancelled']

Активные заявки в срок:
статус не completed;
статус не cancelled;
дата перевозки сегодня или позже.

Загрузка водителей:
для каждого водителя считается количество выполненных перевозок за выбранный период.

Пример:
Иванов Иван Иванович - 3 перевозки
Петров Петр Петрович - 2 перевозки

15. КАК ПРОВЕРИТЬ ВРУЧНУЮ

Автоматический расчет стоимости:
1. Создать новую заявку.
2. Выбрать тип груза, например Бетон.
3. Указать массу, например 8.5 т.
4. Поле стоимости оставить пустым.
5. Сохранить заявку.
6. Проверить, что стоимость стала 12200 руб.

Расчет по объему:
1. Создать заявку.
2. Выбрать Песок.
3. Массу оставить пустой.
4. Указать объем 10 м3.
5. Стоимость оставить пустой.
6. После сохранения стоимость должна быть 5500 руб.

Проверка ручной стоимости:
1. Создать заявку.
2. Указать массу или объем.
3. Ввести стоимость вручную, например 12345 руб.
4. После сохранения стоимость должна остаться 12345 руб.

Проверка загрузки транспорта:
1. Создать заявку с массой 8 т.
2. Назначить транспорт грузоподъемностью 10 т.
3. В карточке заявки или перевозки должна отображаться загрузка 80%.

Проверка превышения грузоподъемности:
1. Создать заявку с массой 12 т.
2. Попробовать назначить транспорт грузоподъемностью 10 т.
3. Система должна запретить назначение и показать ошибку:
"Выбранное транспортное средство не подходит по грузоподъемности."

Проверка отчетов:
1. Открыть раздел отчетов.
2. Выбрать период и тип груза.
3. Проверить карточки средней стоимости, процента выполненных заявок и просроченных заявок.
4. Проверить диаграмму загрузки водителей.


16. ИТОГОВОЕ ОПИСАНИЕ

В ходе доработки существующая система управления грузоперевозками была расширена без изменения общей архитектуры.
Были добавлены расчетные механизмы, которые помогают менеджеру по логистике быстрее оформлять заявки и контролировать ресурсы.

Автоматический расчет стоимости уменьшает ручной ввод и делает расчет прозрачным.
Тип груза позволяет учитывать различие тарифов для песка, щебня и бетона.
Проверка загрузки транспорта предотвращает ошибочное назначение машины, которая не подходит по грузоподъемности.
Расширенная отчетность дает менеджеру сводную картину по стоимости, выполнению заявок, просрочкам и загрузке водителей.

Все изменения встроены в существующий Django-проект, используют текущие модели, формы, шаблоны и Bootstrap-интерфейс.
Для нового поля типа груза была создана миграция, остальные показатели рассчитываются динамически без усложнения структуры базы данных.
